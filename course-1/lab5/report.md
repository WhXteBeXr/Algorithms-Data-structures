### Теоретическое обоснование

Перегрузка операторов - механизм C++, позволяющий задать собственное поведение стандартных операторов (`+`, `-`, `*`, `/`, `==`, `<`, `[]`, `()`, `<<` и других) для объектов пользовательских типов. Благодаря ей вместо вызова `c = a.add(b)` можно писать `c = a + b`. Код становится короче и читается как математическая формула. При этом нельзя изменить приоритет, ассоциативность и количество операндов оператора, нельзя вводить новые операторы и переопределять их для встроенных типов. Не перегружаются операторы `::`, `.`, `.*`, `?:`, `sizeof`, `typeid`.

Оператор перегружается как функция со специальным именем `operator@`, где `@` - знак оператора. Её можно объявить внутри класса (метод) или вне класса (свободная функция):

```cpp
// метод класса: левый операнд - *this
Matrix operator+(const Matrix& other) const;

// свободная функция: оба операнда передаются параметрами
Matrix operator*(double k, const Matrix& m);
```

У метода левый операнд всегда объект своего класса, а доступ к закрытым полям есть автоматически. Свободная функция не принадлежит классу, поэтому левым операндом может быть значение любого типа (например, `2 * m`), но для доступа к закрытым полям её нужно объявить дружественной.

Дружественная функция - функция, которая не является членом класса, но имеет доступ к его закрытым и защищённым членам. Она объявляется внутри класса с ключевым словом `friend`, не наследуется и нарушает инкапсуляцию, поэтому применяется только при необходимости.

Правила выбора способа перегрузки:

- операторы `=`, `[]`, `()`, `->` и составное присваивание (`+=`, `-=` и т.п.) перегружаются как методы;
- операторы `<<` и `>>` всегда перегружаются как дружественные функции, так как левый операнд - поток, а не объект класса;
- бинарные операторы, где левый операнд может быть другого типа (число * объект), перегружаются как дружественные функции для симметричности;
- остальные бинарные операторы удобнее оформлять методами;
- префиксные `++` и `--` возвращают ссылку на изменённый объект, постфиксные принимают фиктивный параметр `int` и возвращают копию старого значения.

Класс, который хранит данные в динамической памяти, должен соблюдать «правило трёх»: деструктор, конструктор копирования и оператор присваивания. Оператор присваивания должен проверять самоприсваивание и возвращать ссылку на `*this`. Операторы `explicit operator T()` позволяют явно преобразовать объект к другому типу и запрещают нежелательные неявные преобразования.

## Контрольные вопросы

### 1. Что такое перегрузка операторов и зачем она нужна?

**Перегрузка операторов** - механизм, позволяющий определить собственное поведение стандартных операторов C++ для объектов пользовательских классов.

Она нужна, чтобы:

- код читался естественно, как работа со встроенными типами;
- операции можно было записывать компактно и цепочками (`a + b - c * d`);
- интерфейс класса был привычен для других программистов.

```cpp
c = a.add(b);   // без перегрузки
c = a + b;      // с перегрузкой
```

### 2. Какие операторы нельзя перегружать в C++?

Нельзя перегружать:

- `::` - разрешение области видимости;
- `.` - доступ к члену объекта;
- `.*` - доступ к члену через указатель на член;
- `?:` - тернарный оператор;
- `sizeof` и `typeid`;
- операторы приведения `static_cast`, `dynamic_cast`, `const_cast`, `reinterpret_cast`;
- операторы препроцессора `#` и `##`.

Кроме того, нельзя изменить приоритет, ассоциативность и количество операндов оператора, придумать новый оператор или переопределить оператор для встроенных типов (например, `int + int`).

### 3. В чём разница между перегрузкой оператора как метода класса и как дружественной функции?

**Метод класса:** левый операнд - текущий объект (`*this`), доступ к закрытым членам есть автоматически, а неявное преобразование типа возможно только для правого операнда.

**Дружественная функция:** не является членом класса, оба операнда передаются параметрами, доступ к закрытым членам даёт ключевое слово `friend`, а неявное преобразование возможно для обоих операндов. Поэтому левым операндом может быть значение другого типа.

```cpp
class Matrix {
public:
    Matrix operator+(const Matrix& other) const;           // метод: a + b
    friend Matrix operator*(double k, const Matrix& m);    // друг: 2 * m
};
```

### 4. Для каких операторов предпочтительнее использовать дружественные функции?

Дружественные функции предпочтительны для:

- операторов `<<` и `>>`, потому что левый операнд - поток, а не объект класса;
- бинарных операторов, где левый операнд имеет другой тип (`число * объект`);
- операторов, которые должны быть симметричными (`a * b` и `b * a` для разных типов);
- функций, которые работают сразу с двумя разными классами.

В работе дружественными сделаны `operator*(const SparseMatrix&, double)`, `operator*(double, const SparseMatrix&)`, `operator<<` и `operator>>`.

### 5. Как перегрузить префиксный и постфиксный инкремент? Чем они отличаются?

Префиксная форма не имеет параметров и возвращает ссылку на уже изменённый объект. Постфиксная форма получает фиктивный параметр `int` (только для отличия от префиксной) и возвращает копию объекта до изменения.

```cpp
Counter& operator++() {        // ++obj
    ++value;
    return *this;
}

Counter operator++(int) {      // obj++
    Counter temp = *this;
    ++value;
    return temp;
}
```

Постфиксная форма менее эффективна, так как создаёт временную копию.

### 6. Почему операторы `<<` и `>>` нельзя перегрузить как методы класса?

Если оператор перегружен как метод, его левым операндом всегда является объект этого класса. В выражении `std::cout << obj` левый операнд - объект потока `std::ostream`, а изменить стандартный класс мы не можем. Если сделать `<<` методом нашего класса, придётся писать `obj << std::cout`, что неестественно.

Поэтому эти операторы перегружаются как свободные функции. Обычно они объявляются дружественными, чтобы иметь доступ к закрытым полям.

### 7. Что такое дружественная функция? Каковы её особенности?

**Дружественная функция** - функция, которая не является членом класса, но имеет доступ к его закрытым (`private`) и защищённым (`protected`) членам.

Особенности:

- объявляется внутри класса с ключевым словом `friend`;
- не является членом класса, поэтому у неё нет указателя `this`;
- не наследуется;
- нарушает инкапсуляцию, поэтому используется только при необходимости;
- на неё не влияют спецификаторы доступа (`public`, `private`), в секции которых она объявлена.

### 8. В каких случаях стоит использовать дружественные классы?

Дружественный класс стоит использовать, когда два класса тесно связаны и одному из них нужен полный доступ к внутреннему устройству другого. Типичные примеры: контейнер и его итератор, список и его узлы.

```cpp
class MyClass {
    int secret;
    friend class FriendClass;   // FriendClass видит secret
};
```

Дружба не симметрична (если A - друг B, то B не обязательно друг A), не транзитивна и не наследуется.

### 9. Что такое оператор преобразования типа? Как его перегрузить?

**Оператор преобразования типа** позволяет преобразовать объект класса к другому типу. Он объявляется как метод `operator T() const`. Тип возвращаемого значения не указывается, он входит в имя оператора.

Ключевое слово `explicit` запрещает неявные преобразования, поэтому использовать такой оператор можно только с явным приведением.

```cpp
explicit operator double() const { return norm(); }

double n = static_cast<double>(matrix);
```

В работе реализованы `explicit operator double()` (возвращает норму матрицы) и `explicit operator bool()` (проверяет наличие ненулевых элементов).

### 10. Как перегрузить оператор `[]` для доступа к элементам?

Оператор `[]` перегружается как метод класса с одним параметром (индексом). Обычно создают две версии: неконстантную, которая возвращает ссылку (для записи), и константную (для чтения). Внутри проверяют границы и при выходе за них бросают исключение.

```cpp
double& operator[](int k) {
    if (k < 0 || k >= size) {
        throw std::out_of_range("Индекс вне диапазона");
    }
    return values[k];
}

const double& operator[](int k) const;   // версия для константных объектов
```

В классе `SparseMatrix` оператор `[]` возвращает k-й хранимый (ненулевой) элемент.

### 11. Что такое функтор? Как перегрузить оператор `()`?

**Функтор** - объект, который можно вызывать как функцию. Для этого в классе перегружается оператор вызова `()` как метод с любым нужным числом параметров.

```cpp
class Adder {
    int amount;
public:
    Adder(int a) : amount(a) {}
    int operator()(int x) const { return x + amount; }
};

Adder add5(5);
int r = add5(10);   // 15
```

В `SparseMatrix` оператор `()` возвращает элемент матрицы по двум индексам: `m(i, j)`.

### 12. Как перегрузить оператор `new` и `delete`?

Операторы `new` и `delete` перегружаются либо глобально, либо как статические методы класса. `operator new` принимает размер в байтах и возвращает `void*`, `operator delete` принимает `void*`. Для массивов перегружаются отдельные `new[]` и `delete[]`.

```cpp
class Item {
public:
    void* operator new(std::size_t size) {
        // собственное выделение памяти (при неудаче нужно бросить std::bad_alloc)
        return ::operator new(size);
    }
    void operator delete(void* ptr) {
        ::operator delete(ptr);
    }
};
```

Перегрузка нужна для собственных схем управления памятью: пулов, отладки утечек, подсчёта выделений. Конструктор вызывается уже после `operator new`, а деструктор - до `operator delete`.

### 13. Какие проблемы возникают при перегрузке операторов `&&`, `||` и `,`?

У встроенных `&&` и `||` действует короткая схема вычисления: если результат понятен по левому операнду, правый вообще не вычисляется. Перегруженная версия - это обычный вызов функции, поэтому оба операнда вычисляются всегда. В результате код ведёт себя не так, как привыкли, и может появиться лишнее выполнение побочных эффектов, например проверка указателя перед обращением к нему перестаёт защищать.

Оператор запятая в встроенном виде гарантирует вычисление слева направо и возвращает правый операнд. Перегрузка меняет эти привычные свойства, поэтому код становится неожиданным.

Из-за этого перегружать `&&`, `||` и `,` не рекомендуется.

### 14. Что такое «правило трёх» в контексте перегрузки операторов?

**Правило трёх** гласит: если класс управляет ресурсом (например, динамической памятью), для него нужно определить деструктор, конструктор копирования и оператор присваивания. Оператор присваивания `operator=` как раз является перегружаемым оператором.

Требования к нему:

- возвращать ссылку на `*this`, чтобы можно было писать цепочки `a = b = c`;
- проверять самоприсваивание `if (this != &other)`;
- выполнять глубокое копирование и освобождать старую память.

Если правило нарушено, объекты после копирования разделяют одну область памяти, что приводит к двойному освобождению. В работе в `SparseMatrix` реализованы все три метода, а составные операторы (`+=`, `-=` и др.) используют корректный `operator=`: `*this = *this + o`.

### 15. Как перегрузить оператор `->`? Когда это может понадобиться?

Оператор `->` перегружается как метод без параметров, который возвращает указатель на объект (или другой объект, у которого тоже перегружен `->`). Выражение `p->member` компилятор превращает в `p.operator->()->member`.

```cpp
class Ptr {
    Data* ptr;
public:
    Ptr(Data* p) : ptr(p) {}
    Data* operator->() { return ptr; }
    Data& operator*() { return *ptr; }
};
```

Он нужен при создании умных указателей (`unique_ptr`, `shared_ptr`), итераторов и классов-обёрток, которые должны вести себя как указатель.
